# 技術仕様書 — ゆりかごの双刃（仮） 第0.1版

> SNES実機の制約内で動くROM（.sfc）を作る前提。特殊チップは使わない。
> 数値は設計目標。プロトタイプで実測して改訂する。

---

## 1. 作れるか？（結論）

**作れます。** エミュレータ（および理論上は実機＋フラッシュカートリッジ）で動く自作ROM、いわゆる「ホームブリュー」として開発します。

ただし品質面の見通しは正直に書いておきます。

| 領域 | 見通し |
|---|---|
| プログラム（65816アセンブリ） | 実現可能。アクションRPGの基本系（移動・当たり判定・敵AI・メニュー・セーブ）は既知の技術の組合せ |
| ゲームデザイン・数値・シナリオ | 実現可能。ただし「手触り」は実際に遊んで調整しないと良くならない。**プレイして感想を返してもらう工程が必須** |
| ドット絵 | **ここが最大の弱点。** AIがコードで生成するドット絵は、当時の市販タイトルの水準（専任グラフィッカー数名が1年かけた絵）には届きません。第一版は「遊べる仮絵」と割り切るか、絵だけ人が描く体制が必要 |
| 音楽・効果音 | 作曲データ自体は書けるが、当時の名作級の楽曲品質は保証できない。音色（サンプル）も自作かライセンス確認済み素材が必要 |
| 物量（10時間） | 120部屋・35種の敵・全テキスト。段階的に作る。一気には出来ない |

→ まず**序章だけの縦切り（垂直スライス）**を作り、手触りを確認してから量産に入るのが現実的。

## 3. 画面

### 3.1 BGモード

| 場面 | モード | BG1 | BG2 | BG3 |
|---|---|---|---|---|
| フィールド・ダンジョン・町 | Mode 1 | 地形下層（16色） | 地形上層・屋根・木の葉（16色） | HUD・会話窓・雨（4色、優先度高） |
| タイトル・樹を登る演出・終章背景 | Mode 7 | 回転拡大する樹／空 | — | — |

- 解像度 256×224、60fps固定。処理落ちは「敵の更新を隔フレームに間引く」で吸収し、自機の操作は必ず毎フレーム処理する。
- **慈雨の表現**：BG3に雨タイルを流し、カラー加算（半透明）で重ねる。会話窓が開く時はウィンドウ機能で雨を切り抜く。
- HDMA：空のグラデーション、過治癒時の画面の波打ち、ジャスト回避時の暗転。

### 3.2 スプライト（OBJ）

- サイズ設定：16×16／32×32。
- ハード制約：全128枚、**1ライン32枚・34タイル分まで**。これを超えると欠ける。
- 割り当て方針：

| 対象 | 構成 | 枚数 |
|---|---|---|
| グレン本体 | 32×32 ×1 | 1 |
| 大剣（暁・宵） | 32×32 ×各1（剣ごとに絵とパレット差替え） | 2 |
| 斬撃エフェクト | 32×32 ×2 | 2 |
| ミレイユ | 32×32 ×1 | 1 |
| 慈力エフェクト | 16×16 ×4 | 4 |
| 通常敵 | 32×32 ×1〜2（最大6体） | 〜12 |
| ボス | 32×32 ×最大12（96×128相当）＋BG2併用 | 〜12 |
| 弾・破片・花びら | 16×16 | 〜24 |
| ダメージ数字 | 16×16（8×8数字2桁を合成） | 〜8 |

- 大型ボス（瘡蓋竜・大樹の心臓）は胴体をBG2で描き、可動部だけOBJにする。
- ちらつき対策：OAMの書き込み順を毎フレームずらす。

### 3.3 パレット

| 範囲 | 用途 |
|---|---|
| BG 0〜1 | BG3用（HUD・文字・雨）4色×8 |
| BG 2〜7 | 地形（エリアごとに差替え） |
| OBJ 0 | グレン |
| OBJ 1 | ミレイユ |
| OBJ 2 | 暁手の剣（剣ごとに差替え） |
| OBJ 3 | 宵手の剣 |
| OBJ 4〜6 | 敵（エリアごとに差替え） |
| OBJ 7 | エフェクト（半透明対象） |

### 3.4 VRAM配分（64KB）

| 領域 | サイズ |
|---|---|
| BG1/BG2 タイル（4bpp） | 24KB（768タイル） |
| BG3 タイル（2bpp：文字・HUD・雨） | 4KB |
| BG1〜3 タイルマップ（各64×32） | 12KB |
| OBJ タイル（4bpp） | 16KB（512タイル） |
| 予備・文字描画バッファ | 8KB |

- グレンのアニメは全フレームをVRAMに置けないため、**必要なコマだけ毎フレームVBlank中に転送**する（8方向は左右反転で5方向分の絵）。

### 3.5 アニメーション物量（目安）

| 対象 | コマ数 |
|---|---|
| グレン | 待機2／歩行4／連斬4段×3／溜め3／回避3／被弾2／倒れ3 … 5方向で約150コマ |
| ミレイユ | 待機2／歩行4／詠唱3／整骨拳4／被弾2／ひざをつく2 … 約85コマ |
| 通常敵 | 1種あたり12〜20コマ×28種 |
| ボス | 1体あたり40〜80コマ |

→ 絵の総量がプロジェクト最大の工数。**第一版は方向数を4方向に減らす選択肢あり**（未決事項）。

## 5. テキスト

- 文字セット：ひらがな・カタカナ・英数記号＋漢字約300字（小学校低〜中学年程度＋固有用語）。
- フォント：12×12ドットを16×16セルに描画（BG3、2bpp）。会話窓は18文字×3行。
- 当時の作品と同じく**ひらがな主体**で書く。仕様書内の表記（漢字多め）とゲーム内表記は別。
- フォントは自作、または再配布可能ライセンスのビットマップフォントを確認の上で使用。
- 台本量の見積り：約2,500ウィンドウ（約10万文字）。辞書圧縮して約80KB。

## 7. メモリ（WRAM 128KB）

| 領域 | 内容 |
|---|---|
| $0000–$00FF | ダイレクトページ（作業用） |
| $0100–$01FF | スタック |
| $0200–$041F | OAMバッファ |
| $0420–$1FFF | システム変数、エンティティ表 |
| $7E2000– | マップ衝突データ展開先、展開バッファ、文字描画バッファ |
| $7F0000– | 現在エリアのタイルマップ全体、圧縮展開作業域 |

### 7.1 エンティティ

- 同時最大32個：グレン1、ミレイユ1、敵6（ボス戦は部位として最大8）、弾・エフェクト24。
- 1個あたり48バイト：種別、状態、座標（8.8固定小数）、速度、HP、飽和、タイマー、アニメ、当たり矩形ID、AI変数。
- 当たり判定：軸平行の矩形のみ。攻撃矩形×被弾矩形の総当たり（最大でも数十組）。

### 7.2 マップ

- 16×16ドットのメタタイル。1部屋は最大64×64メタタイル（1024×1024ドット）。
- 属性：通行可／壁／水／段差／茂み（斬れる）／育つ足場（過治癒に反応）／砕ける岩。
- 圧縮：LZ系。部屋切替時に展開（暗転中）。

### 7.3 母のAI

- 状態機械：追従／位置取り／詠唱／整骨拳／被弾／ひざをつく／拘束。
- 経路探索は持たない。「グレンの通った座標の履歴（32点）」をたどる追従方式で、壁に引っかかったら3秒後にグレンの隣へ瞬間移動（画面外の時のみ）。

## 9. 開発環境

| 用途 | 道具 |
|---|---|
| アセンブラ | ca65／ld65（cc65付属）。65816の全命令に対応し、リンカ設定でバンク配置を管理しやすい |
| 画像変換 | Pythonスクリプト自作（PNG→SNES 2bpp/4bpp、パレット抽出、メタタイル化） |
| マップ編集 | Tiled（.tmx）→ Pythonで変換 |
| 音 | ドライバ付属のコンパイラ、または自作のMML風テキスト→曲データ変換 |
| ビルド | Makefile。`make` で `cradle-edge.sfc` を出力 |
| 検証 | Mesen 2 のデバッガ・イベントビューア。ヘッドレス実行による自動スモークテスト（起動→タイトル→序章開始までの入力再生） |

言語は**65816アセンブリ直書き**を基本とする【判断】。C言語系のSNES向けツールチェーンもあるが、生成コードが遅く、敵6体＋弾24個を60fpsで回すアクションでは余裕が無くなるため。

### 9.1 リポジトリ構成（予定）

```
cradle-edge/
  docs/          仕様書
  src/           65816アセンブリ
    main.s  nmi.s  input.s  entity.s  player.s  mother.s
    enemy/  boss/  map.s  hud.s  text.s  menu.s  save.s  sound.s
  data/          敵・アイテム・見切りの表（CSV→自動生成）
  gfx/           PNG原画
  maps/          Tiledデータ
  audio/         曲・サンプル
  script/        台本（テキスト）
  tools/         変換スクリプト（Python）
  Makefile
```

## 11. 技術リスク

| リスク | 対策 |
|---|---|
| 1ライン32枚制限でスプライトが欠ける | 敵数上限6、エフェクト優先度制御、OAM順ローテーション |
| 大剣2本の当たり判定とアニメの物量 | 剣を別スプライトにして本体アニメと分離、方向は左右反転で削減 |
| 処理落ち | 敵AIの隔フレーム更新、当たり判定の間引き、FastROM |
| 絵と音の品質 | 仮素材で先に遊びを固め、素材は差替え可能な構造にしておく |
| エミュレータ依存の挙動 | 精度の高いbsnes／Mesen 2を基準にし、未定義動作に頼らない |
| 日本語フォントの権利 | 自作を基本とする |
